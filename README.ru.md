# ayla-tools-contract

![Баннер ayla-tools](assets/banner.png)

Общий **UI-free контракт сигналов** для семейства расширений Ayla tools для [Pi](https://github.com/earendil-works/pi).

Это крошечный модуль без зависимостей: несколько независимых Pi-расширений в одном процессе публикуют небольшие статусные сигналы (quota, voice, memory, transport, working) в одно общее хранилище, а рендерер футера/статуса читает их все, при этом производители ничего не знают друг о друге.

English version: [README.md](README.md).

## Что это — и чего это не является

- **Это:** обычный ESM-модуль с пятью функциями. Без импортов Pi SDK, без UI, без ввода-вывода, без таймеров, без сети. Загружается и тестируется везде, где работает Node.
- **Это не:** фреймворк, шина событий или самостоятельное Pi-расширение. Модуль ничего не рисует и ни на что не реагирует; производители и потребители разделены через простые данные.

Хранилище живёт в слоте `Symbol.for("ayla.footer.signals.v1")` на `globalThis`, поэтому каждая копия модуля в одном процессе Pi (даже из разных пакетов или после перезагрузки модуля) видит одно и то же хранилище.

## Установка

Это **библиотека для разработчиков**, не Pi-расширение. Установка через `pi install` сама по себе ничего видимого не даст. Пакет не опубликован в npm registry; установите публичный Git source в Node-проект:

```sh
npm install git+https://github.com/kekma-dot/ayla-tools-contract.git
```

После этого import ниже работает. Сохраните созданный lockfile, чтобы зафиксировать фактическую ревизию. Автор Pi-пакета также может встроить точную копию `index.mjs`, сохранив MIT-лицензию и SHA-256. Неизменный ключ `Symbol.for("ayla.footer.signals.v1")` позволяет копиям разделять одно хранилище процесса.

## Быстрый старт (5 строк)

```js
import { publishSignal, readSignals } from "ayla-tools-contract";

publishSignal("voice", { state: "connected", microphone: "ok" }); // производитель владеет одним scope
console.log(readSignals().voice);                                  // потребитель читает снимок
publishSignal("voice", undefined);                                 // очищает только scope "voice"
```

## API

| Функция | Поведение |
|---|---|
| `signalStore()` | Возвращает общее на процесс хранилище, создавая его при первом вызове. |
| `publishSignal(scope, value)` | Записывает `value` в один scope. Каждый производитель владеет ровно одним scope. `undefined` очищает **только этот scope**. |
| `readSignals()` | Возвращает свежий неглубокий снимок `{ quota, voice, memory, transport, working }`; незаполненные scope — `null`. Объекты scope передаются по ссылке — считайте их read-only. |
| `resetSignals()` | Тестовый помощник: заменяет всё хранилище. Продакшн-потребители не должны его вызывать — он стирает чужих производителей. |
| `formatCountdown(ms)` | Форматирует миллисекунды как `59m` / `1h30m` / `2d1h`; возвращает `""` для нечисловых или истекших значений. |

Scope контракта фиксированы: `quota`, `voice`, `memory`, `transport`, `working`. Технически производитель может записать и другие ключи, но `readSignals()` сообщает только scope контракта.

## Гарантии и ограничения

- Общее состояние на процесс by design: переживает перезагрузку модуля внутри процесса (`/reload`) и общее для совместно загруженных пакетов. Сбрасывается только полным перезапуском процесса.
- Без валидации payload: формы сигналов — договорённость производителя и потребителя по каждому scope. Scope должны быть доверенными константами расширения, не входом от tools/сети. Владение — соглашение, не access-control: любое расширение процесса может читать и менять store. Не передавайте через сигналы секреты и приватный контент.
- Node.js ≥ 22.18.

Вне `node_modules` или встроенной копии потребителя ничего не записывается; удаляйте зависимость или встроенный файл вместе с потребителем.
